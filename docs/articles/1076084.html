Technical Specification: Not "Create hype reels for me," but "You are a senior n8n solutions architect"

Everyone understands that an LLM is not a magician or a psychic. A simple rule: the more precise the input, the fewer hallucinations on the output. Therefore, in Cline, I didn't write "invent an autoposting system with Telegram alerts," but a maximally (it seems) structured brief with iterations. A shortened version of the actual prompt became this:

ROLE
You are a senior n8n solutions architect. You produce production-ready,
importable n8n workflow JSON. You never invent API parameters or node
fields; when unsure, you say so explicitly.

PROJECT CONTEXT
BACKLOG: "AutoContent-Factory v1.0" — an autonomous pipeline
for AI trend analysis, multimedia generation, and Instagram autoposting
based on self-hosted n8n.

PIPELINES:
1 — competitor parsing (ScrapeCreators API), virality formula
1.5 — semantic filter (LLM-reranker, relevance threshold)
2 — AI dispatcher (strict JSON: scenario/video prompt/caption)
3 — multimodal generation (video/voice/cover via OpenRouter)
5 — autoposting (Instagram Graph API)

API FACTS (from official docs)
- 1 credit = 1 request; cache hits = 0 credits
- GET /v1/instagram/user/reels — metrics WITHOUT caption
- GET /v2/instagram/media/transcript — 10–30 s, timeout >= 60 s
- HTTP 402 = out of credits; 5xx = transient

RULES
One contour per message. No secrets. Defensive JS (try/catch,
null-checks). If ambiguous — ask ONE clarifying question.

I'll highlight the key techniques that saved my nerves:

  • Role instead of a request. The "Senior Architect" role changes the generation tone: the model writes defensively, not conversationally – simplified.

  • Explicitly forbidden to invent parameters. If unsure, say so and add to the "VERIFY MANUALLY" list.

  • Iterations by pipeline. One pipeline per message – the model doesn't get confused by dependencies.

  • Output Contract = One JSON block + import instructions + list of questionable parameters.

The only thing I forgot to provide the model with, at the very end of assembling the finished workflow, was detailed technical documentation. That would have made the article more detailed and easier to write!:‑)

Workflow Architecture: 5 Pipelines, 127 Nodes

Honest workflow arithmetic, so no one has to recalculate for me: 127 = 113 nodes in five pipelines (23 + 17 + 17 + 37 + 19) + 2 input triggers (Schedule and Manual) + 4 disabled stubs for future iterations + 8 documentation stickers. The number of working nodes is accordingly 115: 113 pipeline nodes + 2 triggers. I'll explain each pipeline in more detail:

1st Pipeline: Let's call it "Reconnaissance" (23 nodes)

The scheme is as follows: Schedule (24h) – list of competitors – Reels via ScrapeCreators – virality math: views > avg × 2.5 – tag TRENDING – for trending posts, fetch caption (/v1/instagram/post) and transcript (/v2/instagram/media/transcript, timeout 60s; null – caption-only). For now, the competitor list consists of static test handles; for real implementation, desired niches will be substituted.

Pipeline 1.5: Let's call it "Semantic Filter" (17 nodes)

LLM-reranker evaluates relevance in the chosen niche (I chose automation in n8n) on a scale of 0–1. For the reranker role, I chose Qwen3 Reranker 8B via chat/completions. Its prompt includes a rubric with live examples: "Building an LLM Agent in n8n for Request Processing" = 0.95 (core niche), "How to Set Up ChatGPT" = 0.75 (AI productivity), AI in general = 0.5–0.69, related (SaaS business) = 0.2–0.49, personal vlogs = 0.0–0.19. Anything below the threshold goes to the dead end Drop: Below Threshold. Without this pipeline, this "factory" would generate content about a randomly popular personal vlog of a content creator.

2nd Pipeline: AI Dispatcher (17 nodes)

The model doesn't copy someone else's post! Why churn out similar content. It "extracts the DNA of virality" (hook, trigger, format, call to action) and creates an original idea. Output – a strict JSON schema: angle, hooks, voice_script (120–160 characters), video_prompt, instagram_caption. A valid draft falls into Google Sheets with the status DRAFT.

3rd Pipeline: Media Workshop (37 nodes)

Video: seedance-2.0-mini with a fallback to veo-3.1-lite, asynchronous polling (Wait 10s × 20 attempts). Voice: TTS outputs raw PCM, which is converted to WAV on the fly. The configuration in "Clean Voice Script" explains another thing: the flags ARCHIVE_TO_DRIVE=false and MUSIC_ENABLED=false – this is an economy config: seedance-2.0-mini/ 480p/ 5s with a fallback to veo-3.1-lite. Cover: image generation with a neon tech vibe. Everything with retries, warnings, and statuses MEDIA_READY / MEDIA_FAILED.

Final Pipeline: Distribution (19 nodes)

Inside – another surprise: video and voice merging via ffmpeg (Write -Exec -Read in /tmp). Voice is optional: no voice = video goes as is under the key final_mp4. Plus, the Instagram container has its own polling FINISHED - Wait 5s * 12.

Google Drive (upload + share publicly) – Instagram Graph API (REELS container – publish) – permalink – update Sheets – report to Telegram.

The Gem: PCM to WAV on the Fly

The TTS model outputs raw PCM (24 kHz, 16-bit, mono) without a container – neither n8n nor Instagram understands such a stream. The model generated a Code node that attaches the correct RIFF header:

function wavHeader(len) { 
  const sr = 24000, ch = 1, bits = 16;
  const b = Buffer.alloc(44);
  b.write('RIFF', 0); b.writeUInt32LE(36 + len, 4); b.write('WAVE', 8);
  b.write('fmt ', 12); b.writeUInt32LE(16, 16); b.writeUInt16LE(1, 20);
  b.writeUInt16LE(ch, 22); b.writeUInt32LE(sr, 24);
  b.writeUInt32LE(sr * ch * bits / 8, 28); b.writeUInt16LE(ch * bits / 8, 32);
  b.writeUInt16LE(bits, 34); b.write('data', 36); b.writeUInt32LE(len, 40);
  return b;
}

const pcm = await helpers.getBinaryDataBuffer(i, 'voice_mp3');
const wav = Buffer.concat([wavHeader(pcm.length), pcm]);
bin.voice_mp3 = await helpers.prepareBinaryData(wav, 'voice.wav', 'audio/wav');

I double-checked every byte: the 44-byte header – all calculated, not hardcoded, and using n8n's correct binary helpers, not naive item.binary.data

Static Data: Accumulator for the Loop Without Duplicates

Trend collection logic: loop through handles in the niche, carefully collect data in the workflow's static data, and at the end, read this buffer, clean it, and perform final deduplication by URL:

// inside the loop:
const sd = $getWorkflowStaticData('global');
sd.acf_trending = sd.acf_trending || [];
sd.acf_trending.push(...$input.all().map(i => i.json));

// after the loop:
const rows = sd.acf_trending || [];
sd.acf_trending = [];               // state does not leak between runs
const seen = new Set();
return rows.filter(r => {
  const key = r.post_url || r.shortcode;
  if (seen.has(key)) return false;
  seen.add(key); return true;
}).map(r => ({ json: r }));

402 is Not Equal to 5xx: Two Different Service Deaths

The system distinguishes between "service is temporarily down" and "ran out of credits." A universal check that the model stamps in every error branch:

const e = $json.error || {};
const sc = Number($json.statusCode || e.statusCode || e.status || 0);
const msg = String(e.message || '');
const is402 = sc === 402 || msg.indexOf('402') !== -1;

The policy in this scheme is as follows: 402 = alert to Telegram + StopAndError (retrying without money is pointless); 5xx – retry multiplied by 3 = fail-open: the handle is skipped, the pipeline lives on. TTS failure doesn't kill the reel; it just goes without voice, with a warning in the table.

The virality formula in the code is not a magic number in the condition but a named constant:

```javascript
// Phase 1: average views per handle; views > avg * 2.5 => tag TRENDING.
const TREND_MULTIPLIER = 2.5;
```

Underneath it is a defensive wrapper pickNumber(), which extracts the view count from any API response format.

A separate gem is the reranker fail-open node. If Qwen3 fails after three retries, all documents are assigned a neutral 0.5 – which the threshold of 0.75 honestly filters out. The pipeline doesn't break: it just quietly skips the round. The comment in the node explicitly acknowledges this: "0.5 < MIN_RELEVANCE_SCORE (0.75), so the filter drops them; pipeline stays healthy".

Final Binary Merger

HTTP nodes in file mode erase binary data from $input. stealth/ox-alpha itself suggested fetching them directly from the producer nodes, bypassing the current flow:

function grabBinary(nodeNames, keys) { 
  for (const n of nodeNames) {
    try {
      const bin = ($(n).first() || {}).binary || {};
      for (const k of keys)
        if (bin[k] && (bin[k].data || bin[k].fileName)) return bin[k];
    } catch (e) {}
  }
  return null;
}
const vid = grabBinary(['Fetch Video'], ['video_mp4', 'video', 'data']);
const voi = grabBinary(['PCM to WAV', 'Generate Voice'], ['voice_mp3']);
const cov = grabBinary(['Download Cover', 'Normalize Cover'], ['cover_png']);

Where the Model Stumbled and My Own Stumbles

Without this subsection, the article would probably be in the style of a press release, so here's the shortest list of "ailments" (although, as you understand, there were plenty over 60 million tokens):

Model's Mistakes:

  • require(‘crypto’) in the Code node. In n8n, require is not available – I had to force Cline to rewrite it using built-in functions.

  • Google erases binary files. The Google Drive node returns only its JSON, and voice/video were lost after updating the row. The Rebuild Handoff Item node was created to restore the item from the producer nodes.

  • Phantom nodes. A couple of times, the JSON contained type/typeVersion that are not in the current n8n version – I checked manually.

  • Hardcoded IG_USER_ID. The model didn't think to move the ID to credentials – the constant is hardcoded. Okay for testing, but for deployment, it needs to be moved to env.

Where I Messed Up Myself (caught only during manual audit):

  • Reranker threshold was off. In the documentation sticker, MIN_RELEVANCE_SCORE = 0.75, but in the IF node, it was set to >= 0.4 for debugging – and I honestly forgot to change it back. I caught myself on the very same "relevant reel every day". Conclusion: the config should live in one place, not separately in the sticker and the node.

  • Video polling 20 times 10s. During peak hours, the queues for Veo/Seedance can be longer – MAX_ATTEMPTS will need to be increased.

And now, an example of stumbles/mistakes, and why it's not a failure:

Video not generated = draft not lost, marked MEDIA_FAILED. Publishing failed = alert with the reason and a link to Drive for manual upload. A minor detail for the observant: Telegram ate the underscores, and the message proudly displays "MEDIAFAILED" – consider it free markdown censorship.
