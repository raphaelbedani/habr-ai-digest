Assistant-UI

We set aside Open WebUI and turned to the Assistant-UI framework.

Assistant-UI is an open-source TypeScript/React library for building customizable AI-powered chatbot interfaces.

Unlike Open WebUI, this is a set of frontend tools from which you can assemble an interface for your specific task. The library is designed for creating AI chats: it can display responses as they are generated, correctly handle interruptions and retries, support long multi-step dialogues, and integrate with various backend solutions, including custom APIs and LangGraph.

Advantages of Assistant-UI:

1) Full Customization. Since it's a library, the appearance can be changed as desired, and your own components can be written and implemented. If you encounter difficulties, you can refer to project examples on GitHub.

2) Integration with LangGraph. Assistant-UI supports the LangGraph template (a template for integration with the framework used for the graphical representation of the "Idea Bank"). This provides out-of-the-box support for streaming agent state updates, not just response text, allowing for accurate reflection of task progress in the interface. Mechanisms like human-in-the-loop and generative UI are available out of the box.

3) Catalog of ready-made UI components (tool-ui). Over 20 tools for direct user interaction: from tables and checklists to command lines and progress trackers.

Disadvantages of Assistant-UI:

  • Higher entry barrier. Requires knowledge of React.

  • Time and effort. The UI needs to be written and assembled, which affects MVP timelines.

  • Some functionality requires manual refinement. For example, document handling, which was out-of-the-box in Open WebUI.

What we gained with Assistant-UI

In our case, Assistant-UI proved to be a more convenient and suitable tool:

  • Custom Components. We integrated the necessary visualization of the idea development process into the product. It's convenient, clear, and close to the real-life process – this is how people in the team collaborate on a new topic.

  • Integration with LangGraph. Support within the framework allowed us to avoid special workarounds during development. The workflow is architecturally represented within the product as graphs for different stages with possible route changes.

  • Organic human-in-the-loop. Each agent, at the right moment, prompts the user with full context.

Which choice and for which scenarios

Open WebUI is an open-source web interface, convenient when you don't want to write code and need a simple, familiar chatbot. It can be integrated quickly, but customization will require significant effort. Thus, it's a good choice for a quick start when you need a ready-made self-hosted AI product and user interaction is a standard chatbot experience.

Assistant-UI is a framework that provides complete freedom of action. It's suitable for more creative tasks. It takes time to write the foundation, but integrating ready-made tools is facilitated by examples from GitHub. It requires at least a basic understanding of React but offers control over state, streaming updates, tool calling, human-in-the-loop, custom UI components, and direct integration with agent backends like LangGraph.

Where such choices are encountered

The described selection logic is useful not only for the "Idea Bank." It is applicable to many corporate AI solutions:

  • internal AI assistants for employees;

  • AI modules in CRM, ERP, Service Desk, and industry-specific systems;

  • services for processing requests, documents, and inquiries;

  • multi-agent solutions for analytics, hypothesis testing, and recommendation generation;

  • interfaces where AI must not only respond but also guide the user through a process.

In all these cases, the "chat" is often just the top level of interaction. Beneath it lies the corporate flow, state management, agent control, checks, approvals, and domain logic. This is precisely why such products require an interface layer that can coexist with this logic.

Conclusion

When developing AI products, the choice of a frontend tool cannot be reduced to the convenience of a ready-made chat or the speed of the initial launch. In projects with multi-agent logic, human-in-the-loop, and non-standard interface entities, the UI becomes part of the product's architecture.

  • Open WebUI is a strong tool for a quick start when a ready-made universal AI interface is needed.

  • Assistant-UI is a more flexible path when you need to embed AI into a specific business scenario and maintain freedom in interface design.

For us, this meant a simple choice: if the goal is just to show a chat, you can take a ready-made platform. If the goal is to show how an AI service will actually work within a product and business process, you need a tool that allows you to design your own UX around the system's logic. In our case, that tool was Assistant-UI.
