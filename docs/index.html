I Reconsidered My Stance on Obsidian After Building a Second Brain with 219,000 Files

For over a year and a half, I've been building a digital twin: a knowledge base containing my life's data from the past decade, and an agent that uses this base. I started like everyone else, with Obsidian and Claude. My first conclusions came after uploading 219,353 files. For me, Obsidian is now just a viewer, not what I initially thought. The value of this data lies in three things: plain text files on disk, links and interconnections between them, and an agent that reads and writes them directly. This article explains how it's set up now and how many tokens have been spent. My goal was to create a digital twin – a system that thinks and responds like me, remembers everything I remember, and even what I've forgotten. This requires a properly functioning memory, not a vector database with 500-token blocks, but a structured one with history. I installed Obsidian, created a vault, and started dumping notes, documents, and stories – everything. I expected Obsidian to be the home of my memory, the graph to be a functional tool for finding forgotten information, not just a visual, and plugins to cover all my needs: linking notes, creating tables, and connecting to a neural network. I also expected seamless synchronization and for the agent to work with the base through it. Only the graph's aesthetics and the readability of notes met these expectations. Obsidian is not a knowledge base; for me, it's a viewer for a folder of text files. It's beautiful, with a graph and plugins. The agent doesn't need Obsidian at all. Claude Code reads and writes files directly, without bridge plugins or intermediaries. Synchronization also bypasses Obsidian's cloud. Syncthing works well; I have six machines, each with a full data copy. I'm keeping Obsidian for its graph visualization and note readability, but its role is far from what I imagined from reviews and descriptions. Perhaps my initial mistake was (and many make it) dumping everything into text files: chat logs, dumps. The vault grew rapidly, search worsened, and token usage increased due to sifting through irrelevant information. My current data storage and processing are structured in three layers. Layer 1: Facts. Raw data in SQLite databases (Telegram archive, browser history, counters). Questions of 'how much,' 'when,' and 'who' are resolved by database queries, costing zero tokens. Layer 2: Meaning. After selecting notes, I perform value-based search on my GPU, saving tokens. The agent queries it and receives the five closest notes for reading. Layer 3: Thoughts. The AI and I write summaries: decisions, rules, profiles, analyses. Raw information doesn't enter the vault. I use inexpensive tools first: database queries and file searches are free. Value-based search is cheap. The AI model is called last, only when its judgment is needed, and it receives pre-selected information. A mandatory rule: the agent must always retrieve context before starting work. For example, when writing an email, the agent reads the recipient's card, correspondence history, and past interactions. When starting a task, it checks if it's been done before. At the start of a session, it runs the query through search and works based on the input. Second rule: everything processed by the agent is saved. Each saved file undergoes four steps: the original is preserved, a note with a description and source is saved, the search is re-indexed, and links to neighboring notes are added. The note header includes title, date, type, source, machine, and tags. The 'machine' field is crucial as six machines and multiple people write to the vault, aiding in quick orientation. The most useful outcome is my voice profile. A script analyzed all 958,014 of my messages over ten years, collecting statistics on greetings, filler words, introductions, sales pitches, and reminders. Now, when the agent writes as me, it consults this profile to mimic my style. Messages after 2025 were counted separately as AI writing quality varied. Figures: 219,353 text files, 280 concepts (graph core), 5.9 GB Telegram archive (958,014 messages), 6 machines synced via Syncthing, value-based search on GPU. Challenges: Syncthing conflicts with multiple machines writing to one folder (mitigated by 'one file, one writer' rule and conflict monitoring script). Incorrect conclusions due to robots not finding information (now agent searches all locations before concluding absence). High cost of loading files per session (mitigated by measuring token cost of new rules and nightly compression). My logic: raw data to database, meaning to search, thoughts to text files. Violating this costs money. In the end: after 1.5 years, I have a vendor-independent memory: disk files, SQLite, open Syncthing. Obsidian and Claude can be replaced, but the files remain. The agent wakes up knowing the context: decisions made, promises given, yesterday's issues. Everything described is on my GitHub. Feel free to ask questions; I'm happy to share my 1.5 years of setup and reconfiguration.
