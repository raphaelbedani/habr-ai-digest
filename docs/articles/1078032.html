What it is in one paragraph

Input: a whole episode. Output: several ready-made 9:16 clips with dynamic framing, word-by-word subtitles, a watermark, processed audio, cleaned metadata, and sending to Telegram. Between these two points:

episode.mp4  →  transcript  →  signals (audio / faces / cuts / tempo / hooks)  →  LLM moment selection →  segment assembly  →  virtual 9:16 camera  →  layers (subtitles, watermark, music) →  metadata reassembly  →  Telegram

Thirteen stages, each can be turned on and off separately. No command-line flags: the channel's behavior is entirely described by a single config.yaml, because the main work here is parameter tuning, and tuning requires a file that can be diffed and rolled back.

By the numbers: ~7,000 lines of main code, 249 tests with ~3,000 lines, a fully commented demo config of 344 lines.

Article 2 → rendering/face_detector.py

"I Taught a Virtual Camera to Be an Operator" — about why a center crop throws away half the frame, and naive face tracking results in a camera that is physically unpleasant to watch.

The entire described algorithm is in one module:

  1. Detector cascade: MediaPipe → YuNet (ONNX via OpenCV) → Haar Cascade. Failure of any backend does not break the stage.

  2. Hero selection based on saliency (confidence + size + centrality) with hysteresis: face_switch_margin and face_switch_hold_s prevent the camera from ping-ponging between characters.

  3. Filtering: anti-jerk (hard limit on frame-to-frame jump) + low-pass.

  4. Physics: a = k·error − c·v with speed and acceleration limits, a dead zone, predictive lead, and a "live hand" micro-lag.

  5. Composition: eye-level lift, third-rule offset, protective margins to the edges.

  6. Cuts: at an edit cut, the camera doesn't move across the frame but instantly reassembles.

  7. Ken Burns as fallback: without faces, the camera doesn't freeze but gently pans around the last known position of the subject.

Plus, what I didn't talk about in the article: static / operator / action profiles set the basic camera temperament, and any key in dynamic_shorts overrides the profile specifically. Analysis is done at 8 fps, camera states are interpolated to the full frame rate — there's no need to calculate detection on every frame.

Article 3 → analysis/

"Why LLM + Transcript Almost Always Yields Garbage" was the most controversial in the comments, so I'll show specifics for it.

The thesis was this: don't demand correctness from one model in everything. The scene is first described along several independent axes, candidates are deterministically ranked before the model sees them, and the model does exactly what it's good at — judging whether the moment is interesting.

Scoring lives in analysis/moment_scorer.py, and weights are exposed in the config in plain text:

moment_scoring:  cell_s: 0.5              # temporal grid resolution of signals  step_s: 1.0              # sliding window step  max_candidates: 12       # how many remain after NMS  prompt_limit: 8          # how many actually go into the prompt  weights:                 # normalized to sum to 1    transcript: 0.24       # density and content of lines    audio: 0.20            # emotional peaks of sound    face: 0.14             # is there something to focus on vertically    scene: 0.12            # scene changes and movement    pacing: 0.14           # tempo, absence of lulls    hook: 0.16             # strength of the entry in the first 1–2 seconds

score = Σ weight_i · signal_i, then NMS by window overlap. The top of the list goes into the prompt — eight candidates instead of the entire transcript. This is noticeably more stable than free selection and incidentally cheaper in tokens.

The second half, which was almost absent in the article, is what happens after the model's response. analysis/moment_validator.py doesn't take its word for it:

  • duration is recalculated as the sum of segments, not taken from the response;

  • segment overlaps are resolved, boundaries are snapped to speech pauses and edit cuts;

  • moments outside the gpt.min_time–gpt.max_time range are discarded;

  • if nothing remains after filtering — the request is repeated (up to three attempts) with a clarifying suffix, and if that also fails, the list is filled with heuristic candidates.

That is, the episode doesn't crash due to a bad model response — it degrades to purely algorithmic selection. This is perhaps the main practical takeaway from the entire series: quality here is achieved not by finding an ideal solution, but by systematically filtering out bad ones.

And a moment is not "cut a piece from 5:30 to 6:00". It's an assembly edit: segments can be taken from different parts of the episode, pauses are cut out, the hook is always in the first segment, the last is a cliffhanger or a loop to the beginning.

What wasn't in the articles but is in the repository

Tests. 249 of them, completely isolated: OpenAI, Telegram, and Kodik are mocked, the whisper module is replaced with a stub in conftest.py — otherwise, CI would pull torch and download models. mediapipe and anime_parsers_ru are intentionally not installed in CI: the code must degrade to fallback detectors, and this is checked by a test, not a README promise.

Separately, there's test_render_stages.py, where each make_clips stage actually renders a valid mp4, and test_pipeline_e2e.py — an end-to-end run of the channel from video to Telegram. CI runs the fast layer and the render layer at different steps, so it's immediately clear whether the logic broke or the render specifically.

Render layers. Subtitles are rendered word-by-word, with optional re-recognition of the clip by a heavier Whisper model and subsequent LLM text cleaning: spelling is corrected, and exactly one keyword is wrapped in <hl>…</hl>, which the renderer styles separately. Colored emojis are via Pilmoji. Plus, a soft-knee compressor for the dialogue track, a blurred background from the source, and titles with auto-adjusted font size.

Delivery. spoof_metadata reassembles the container without re-encoding (-c copy), completely erases original metadata (-map_metadata -1), and substitutes plausible editor data. The original is deleted only after successful reassembly — the clip is not lost if ffmpeg fails.

What was cut and why

Honestly, so there are no questions:

  • automatic upload to YouTube and TikTok — remains in the private project;

  • publication scheduler;

  • analytics loop (feedback on clip metrics into scoring weights).

The showcase ends with "a ready clip on disk, sent to Telegram." All configuration parameters are reset to neutral values — these are defaults for the first run, not "correct" numbers. There are no keys, access tokens, or third-party media files in the repository: only fonts under SIL OFL are included, music and backgrounds must be provided by the user.

Launch

git clone https://github.com/ialakey/shorts-factory  cd shorts-factory  python -m venv .venv && source .venv/bin/activate   # Windows: .\.venv\Scripts\Activate.ps1  pip install -r requirements.txt  cp .env.example .env      # OPENAI_API_KEY is mandatory  python app.py

Python 3.12+ and ffmpeg with ffprobe in the PATH are required — specifically the binaries, because they are called directly as commands; what's inside imageio-ffmpeg is not enough, it lacks ffprobe. There is a Dockerfile if you don't want to deal with system dependencies of OpenCV.

Recommended order: run a debug launch on test_data/ with debug: true, look at intermediate artifacts, tweak weights — and only then process real episodes.

Known rough edges are also listed, all in the README: uses legacy-API openai==0.28.0, OPENAI_API_KEY is required even for scenarios without LLM (check is done on import in config.py), pilmoji 2.0.4 strictly requires emoji 1.x, and Kodik is blocked by many providers (this stage survives it and is gently skipped).

Conclusion

Three articles described ideas. This repository is the same, but in the form of code that runs and is covered by tests.

The overarching theme of the entire series remains unchanged: no single signal is sufficient. Loud moment ≠ interesting, beautiful line ≠ understandable out of context, perfect face detection ≠ pleasant camera movement. Everything that works here came from a combination of weak signals and careful degradation when one of them failed.
