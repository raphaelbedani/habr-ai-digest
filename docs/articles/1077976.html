How it's set up now and how many tokens have been spent

My goal was to create my digital twin. A system that thinks and responds like me, remembers everything I remember, and even what I've already forgotten. This requires a properly functioning memory. Not a vector database with 500-token blocks, but a normal one, with structure and history.

I installed Obsidian, created a vault, and started putting notes, documents, stories – everything – into it.

What I expected from Obsidian when I installed it: that it would become the place where all my memory resides; that the graph would be my working tool for finding forgotten things, not just a picture; that Obsidian's plugins would cover everything I needed: link notes together, gather them into tables, and connect to a neural network; that synchronization between machines would be its concern, not mine; that the agent could work with the base through it.

Of these, only the fact that the graph is genuinely pleasant to look at and notes are easy to read with the eyes has come true. But Obsidian is not a knowledge base. For me now, it's a program for viewing a folder of text files. It's beautiful, with a graph and plugins.

The agent doesn't need Obsidian at all for its work. Claude Code reads and writes these files directly, without bridge plugins and without an intermediary. Synchronization also bypasses Obsidian's cloud. Syncthing works well; I have six machines, and each has a full copy of the data.

I've kept Obsidian – I enjoy looking at the graph and reading notes with my eyes. But its role is completely different from what I thought when I watched reviews and read descriptions.

Perhaps I made a mistake at first (but many do) – I put everything into text files. Exports of correspondence, logs, dumps. The vault quickly grew in size, search became worse, and token consumption increased as I had to sift through extra information to find what I needed.

Now, my data storage and processing are structured in three layers.

The first layer is facts. Raw data resides in SQLite databases. Here, there's a ten-year Telegram archive of 5.9 gigabytes, of which I personally wrote 958,014 messages, plus browser history and counters. Questions like 'how much,' 'when,' and 'who' are resolved by querying the database and cost zero tokens.

The second layer is meaning. After notes are selected, a search by value is performed. It runs on my video card, so I don't spend tokens. The agent queries it and receives the five closest notes, which it then reads.

The third layer is thoughts. The AI and I write summaries: decisions, rules, people's profiles, analyses. All raw information in its array does not enter the vault at all.

First, I use inexpensive tools. Database queries and file searches cost nothing. Value-based search costs pennies. But the model, which needs to think through all of this, I call last and only where its judgment is needed, and I give it already selected information.

But I have a mandatory rule – the agent must always retrieve context before starting work. Although, perhaps this is basic.

For example, when I write a letter to someone, the agent first reads their card, the correspondence history, and everything I've said about that person before. If I start a task, it first searches if we've done this before. At the start of a session, it automatically runs my question through search and works based on the input.

Second rule: everything that goes through the agent is saved in the vault. Each saved file goes through four steps. The original is saved as is. With it, I save a note with a description and indication of its origin. Then, the search is re-indexed; otherwise, the note exists but cannot be found. And the note gets links to neighboring ones.

The header of a note looks something like this:

---
title: "Voice Profile of Anton"
date: 2026-08-30
type: concept
source: voice_corpus.db (958 014 msgs)
machine: HP17-ZBook
tags: [voice, digital-twin]
---

The 'machine' field is mandatory for me because six machines and several people write to the vault, and if something needs to be quickly oriented, it's important to know which machine did what and who is to blame.

The most useful (or simply illustrative) thing that has grown out of this system is my voice profile.

A script, without token expenditure, went through all 958,014 of my messages over ten years and collected statistics: how I greet, what my filler words are, how I introduce people to each other, how I sell, how I remind people about myself. Now, when the agent writes on my behalf, it consults this profile and doesn't invent its own style but maximally imitates mine.

Messages after 2025 had to be counted separately. Because some of them were already written by robots, and in 2025, they still wrote poorly. Therefore, I excluded their messages.

Figures

219,353 text files in the vault, including correspondence and meeting summaries
280 selected concepts – the core of the graph
5.9 gigabytes of Telegram archive, 958,014 of my own messages
6 machines synchronized via Syncthing, without cloud
Value-based search runs on my video card, no tokens spent here.

My Challenges:

  1. When six machines write to one folder, Syncthing creates conflict files. I introduced the rule 'one file, one writer' and added a watchdog script that counts conflicts and reports when they become numerous.

  2. Next, most often I had incorrect conclusions: if a robot 'didn't find' something, it didn't mean 'it doesn't exist.' The agent searched in one place, found nothing, and created a duplicate. Now the rule is: if it's not found in one place, check all others, another root, a backup, a neighboring machine, and only then can you conclude that it doesn't exist.

  3. Files loaded in each session are expensive. I measured: the session start itself grew to about one hundred thousand tokens. I'm trying to save: for every new rule, I now measure the cost in tokens, and a separate nightly process performs compression.

My logic is structured: raw material into the database, meaning into search, thoughts into text files. Any violation of this boundary costs money.

What's the result

After a year and a half, I have a memory that doesn't depend on any single provider: ordinary files on disk, ordinary SQLite, open Syncthing. Obsidian can be replaced, Claude can be replaced, the files will remain.

The agent wakes up every morning already knowing the context. What we decided. Who we promised. What went wrong yesterday.

Everything described is openly available on my GitHub. If you are building something similar, feel free to ask: I spent a year and a half setting this all up and reconfiguring it, and I don't mind talking about it.
